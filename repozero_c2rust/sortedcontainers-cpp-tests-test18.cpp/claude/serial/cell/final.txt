**Interface decisions worth flagging**

- **C++ iterators → positional cursors.** `find`/`lower_bound`/`upper_bound`/`equal_range` return a `usize` index; `end()` is `len()`; `key_at`/`value_at` stand in for `->first`/`->second`. This maps the original control flow (`if (it != m.end())`) one-to-one without unsafe code. Documented on the type.
- **`m[key]` → `entry_or_default(&key)`.** The name keeps the insert-if-absent side effect visible — it's load-bearing here: at `n=0`, `std::cout << m[test_key1]` is what makes `keys.size()` print `1` instead of `0`.
- **`atoi` is glibc's, not Rust's.** `(int)strtol(...)`, so `"7xyz"`→7, `"2147483648"`→`-2147483648` (wraps, not saturates), `"999…9"`→`-1`. Verified against the binary.
- `size()`/`empty()`/`erase` became `len()`/`is_empty()`/`remove()` to align with `BTreeMap`, which is what a Rust reader will compare this against.
- `update` is a single linear merge of two ordered runs rather than per-entry insertion, with `src` winning on shared keys.
