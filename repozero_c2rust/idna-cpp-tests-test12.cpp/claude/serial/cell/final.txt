## What the C++ library actually does

`idna.hpp` wasn't present, so I derived the full spec black-box from the binary. It's a *toy* IDNA library, not real RFC 3492 punycode:

| API | Inferred behavior |
|---|---|
| `to_ascii` | `"xn--"` + ASCII-lowercased input (unconditionally, even for pure ASCII) |
| `to_unicode` / `punycode_decode` | strips **one leading** `"xn--"` (not per-label: `xn--a.xn--b` → `a.xn--b`) |
| `punycode_encode` | `"xn--"` + input, **case preserved** |
| `is_valid_domain` | `!empty && len <= 255` — no character checks at all (`!@#$%`, spaces, `/` all pass) |
| `is_ascii_domain` / `is_idn_domain` | all bytes `< 0x80` / any byte `>= 0x80` |
| `to_lower` / `normalize` | ASCII-only lowercase, byte-wise (no trimming) |
| `extract_tld` | after last `.`, else whole string; **not** lowercased |
| `count_labels` | dot count + 1 (so `""` → 1, `"."` → 2) |

## Two findings worth flagging

1. **`std::string` is a byte container.** `MÜNCHEN.DE` → `mÜnchen.de`: the `Ü` (`0xC3 0x9C`) passes through untouched while ASCII letters fold. The length limit is also in *bytes*, so 128 `ü` chars = 256 bytes = invalid. I modeled every function on `[u8]` rather than `str` so this matches exactly.
2. **`std::env::args()` would panic** on non-UTF-8 argv, where C++ happily forwards raw bytes. `argv.rs` uses `args_os` + `OsStrExt` to preserve them, verified against `printf 'a\xff\xfe.com'`. Output goes through `write_all` rather than `println!` for the same reason — lossy UTF-8 conversion would corrupt those bytes.
