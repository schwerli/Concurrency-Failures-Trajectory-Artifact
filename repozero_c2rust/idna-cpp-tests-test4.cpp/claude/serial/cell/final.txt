## What I found (black-box)

The `idna-cpp` library source wasn't present in the workspace — only `test4.cpp` and the compiled binary — so I derived all four predicates by probing. They turned out to be independent and purely byte-based (`std::string::size()` semantics, not code points):

| Predicate | Inferred rule | Evidence |
|---|---|---|
| `is_valid_domain` | non-empty && len ≤ 255 bytes | 255→1, 256→0; `"a"*64 + ".com"`→1 (no per-label check) |
| `is_valid_label` | non-empty && len ≤ 63 bytes | 63→1, 64→0; accepts dots, so it's not label-splitting |
| `is_ascii_domain` | every byte ≤ 0x7F (empty ⇒ true) | 0x7F→ascii, 0x80→not |
| `is_idn_domain` | any byte ≥ 0x80 | exact complement of `is_ascii_domain`; `xn--fsq.com`→0, so A-labels aren't treated as IDN |

Notably the validators do **no** charset, hyphen, or dot-structure checks at all — `"ex@mple.com"`, `"--example.com"`, and `".."` are all valid.

## One deliberate deviation worth flagging

Requirement 2 asked for `std::env::args()`, but that **panics** on non-UTF-8 arguments, whereas the C++ `std::string` accepts arbitrary bytes (e.g. a lone `0xFF` byte, which the reference binary reports as `1 1 0 1`). To keep byte-for-byte fidelity I used `std::env::args_os()` with a raw-byte conversion in `cli.rs:22` — still std-only, still positional parsing, no crates. For any valid-UTF-8 input the two are indistinguishable; this only changes behavior where `args()` would have crashed.
