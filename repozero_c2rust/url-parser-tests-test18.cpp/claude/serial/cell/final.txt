## Behaviors recovered black-box from the binary

The header was not present, so I reverse-engineered the semantics by probing. The non-obvious ones:

- **Scheme needs literal `://`** — `mailto:user@example.com` and `http:/example.com` have *no* scheme; the whole string lands in the path. Scheme is ASCII-lowercased; nothing else is (`HTTPÉ://host` → `httpÉ`).
- **Parse order is fragment → query → scheme.** This was the bug the fuzzer caught in my first version: a `://` sitting inside a query or fragment must not create a scheme, so `-1?://://Ahttp#x` is a path-only URL.
- **`authority()` is reconstructed, not the original slice** — so an unparseable port is silently dropped: `http://example.com:99999` reports authority `example.com` and round-trips *lossily*.
- **`has_authority()` tracks the host alone** — `http://user@` renders a non-empty authority yet reports `has_authority() == 0`.
- **Port is `std::stoi` + a range check**: skips leading whitespace, takes a sign, ignores trailing garbage (`80x` → 80, `8 0` → 8), and yields `-1` outside `0..=65535`. `-0` → port 0.
- **Host splits on the first `:`**, so IPv6 literals are truncated: `http://[::1]:8080/p` → host `[`, port `-1`. Faithfully reproduced rather than "fixed".
- **`to_string()` emits the authority only alongside a scheme** — `://host` parses to host `host` but renders as the empty string.
- **`is_valid()` = has a host **or** a path**, independent of scheme.
