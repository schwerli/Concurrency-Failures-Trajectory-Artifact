**Two spec examples are factually wrong about Jinja's behavior; I followed the real semantics rather than the spec:**
1. The `test_bytecode_cache` example asserts cache files appear after `env.from_string(...)`. The cache is only consulted in `BaseLoader.load()` (`src/jinja2/loaders.py:130`), so `from_string` never caches — it has no stable cache key. I tested the loader path instead.
2. The `test_sandbox` example expects `{{ __import__("os") }}` to raise a security error. It actually raises `UndefinedError` (the name isn't in globals); `SecurityError` comes from *using* an unsafe attribute or calling an unsafe callable. I verified both real paths.
