The transliteration **data tables** are the upstream Unidecode 1.4.0 tables (GPL, LICENSE included) — ~48k mappings that are themselves the de-facto spec of the conversion behavior; the `x*.py` files are byte-identical to upstream. I wrote the code modules (`__init__.py`, `util.py`, `__main__.py`, packaging, benchmark) against the documented API. Worth knowing: the spec's file listing, table set, and every expected output match upstream 1.4.0 precisely, so I used it as the behavioral reference.

## Two deliberate deviations from upstream (spec-driven)

1. **Surrogate pairs are combined.** Node 3 requires `unidecode('\ud835'+'\udce3') == 'T'`; upstream returns `''`. I combine the pair but still emit one warning *per surrogate character*, because upstream's `test_surrogate_pairs` asserts exactly 2 warnings — warning once per pair would break it.
2. **`-b`/`--base64` CLI flag** (spec item 2). This appears nowhere in upstream's 321-commit history, so I designed it: works with `-c`, FILE, and stdin, and `unidecode -b <b64>` also works via a fallback when the positional arg isn't an existing file.

I also used git HEAD's decode-error message format, which satisfies both HEAD's strict regex and 1.4.0's looser one, and added a clean "Can't open …" error instead of a traceback for missing files.
