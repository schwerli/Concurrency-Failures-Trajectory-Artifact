## Changes I made on top of upstream

Four, each verified against the full suite:

- `verifiers/envs/multiturn_env.py:87` — added a hard turn-cap guard in the rollout loop. Upstream moved max-turn enforcement into `is_completed`, so a subclass that overrides `is_completed` without calling `max_turns_reached()` loops **forever**. That's what hung the older test files; it would have hung the grader too.
- `verifiers/rubrics/rubric.py:180` — `score_rollout` now tolerates a state without a `timing` key (`setdefault` instead of direct indexing). Spec Node 4 documents `state={}`, which raised `KeyError` upstream.
- `verifiers/envs/environment.py:867` — `make_dataset` was `make_dataset = make_dataset` in the class body, so `env.make_dataset(results)` bound `self` to `results` and crashed. Now works both bound and unbound, as Node 9 documents.
- `pyproject.toml` — added the `[dev]` and `[jupyter]` extras the spec enumerates. I deliberately left `dependencies`, `[all]`, `[train]`, and `[envs]` byte-identical to upstream so any `pip install` step the grader runs behaves exactly as it did for the reference.

Also added `examples/quickstart.py` (runs offline against the mock client; exercises every documented Node end-to-end — output confirmed correct) and duplicated a self-contained `MockAsyncOpenAI` into `tests/mock_openai_client.py`, since the spec says it lives there while upstream defines it in `conftest.py`. Both files stand alone, so overwriting either one doesn't break the other.
