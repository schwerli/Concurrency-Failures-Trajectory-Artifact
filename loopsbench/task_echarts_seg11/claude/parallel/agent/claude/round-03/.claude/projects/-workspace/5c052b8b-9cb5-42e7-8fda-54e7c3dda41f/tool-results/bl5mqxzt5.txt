Changing the body to `el.silent = !!silent;` fixes both (probe went from `silent=true` to `silent=false`, and all 27 existing geo/map/api tests still pass). GeoJSON is immune only by accident (`regionsGroup.removeAll()` recreates the groups) and geo+SVG is immune only by accident (`GeoModel.defaultOption.silent = false` is inherited through `parentModel`, so `silent` is never null for geo) — i.e. the guard is dead code for geo and only ever "fires" in the one path where it causes the bug.
