**Design choices** (all self-consistent with the given `genData.py` block format — payload, a zero separator, then the next-block address):
- Buffer slots are `blkSize + 1` bytes (flag byte + payload), so `BUF_SIZE 520 / 65 = 8` blocks; every operator stays inside that limit (worst case: 7 = 6 hash-bucket blocks + 1 input block).
- `pushToWrite` flushes lazily, so the `next` chain is always valid and terminates with 0; it packs 7×8-byte selection tuples, 14×4-byte projection values, or 4×12-byte join tuples per block.
- Hash partitions: `HASH_PER_BLK` tuples + a tuple count + next address; bucket *i* chains from `addr + i*100`, all inside the address range `main.cpp` cleans up.
- Sort: 3 runs for R / 5 for S (M−1 = 7 blocks per run), then a one-pass multi-way merge.
- Optimiser splits `&`-conjunctions and sinks each predicate as deep as it is provably safe: through a PROJECTION only when the attribute survives it, to the JOIN operand that owns the attribute (query 3's `ESSN` cannot be attributed to `WORKS_ON` or `PROJECT`, so it correctly stops above the join).
