  Vue users often store the chart instance inside `ref()` or `reactive()`, but proxying the ECharts instance can interfere with instance methods and create hard-to-debug integration issues.

  ## Desired outcome

  An ECharts instance should be treated as raw when used from Vue so framework reactivity does not wrap it and break normal instance behavior.

  ## Acceptance signals

  Storing the chart instance inside Vue state no longer causes proxy-related surprises, and methods like updating options or dispatching actions keep working normally.
