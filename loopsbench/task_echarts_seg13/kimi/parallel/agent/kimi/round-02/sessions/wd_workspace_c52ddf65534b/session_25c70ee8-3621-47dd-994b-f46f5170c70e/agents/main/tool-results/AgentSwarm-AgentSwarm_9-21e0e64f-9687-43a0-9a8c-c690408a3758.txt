**What the bug was:** In `src/util/jitter.ts`, the overlap-avoidance placement stored placed points in a circular doubly-linked list that was only kept ordered along whichever direction each point was inserted. Once points were inserted in mixed directions, the ordering was corrupted, so the directional walk in `placeJitterOnDirection` skipped existing items and produced overlapping placements; also, after pushing `y` past one item it never rechecked the others, so it could land on top of a different point. Both cases made it fall back (or worse, accept an overlapping spot) even when free space existed inside the jitter band.

**Fix (matches upstream apache/echarts PR #21067 plus its follow-up afed7bfc, i.e. current master logic):**
- Replaced the linked-list store with a plain `JitterData[]` (`next`/`prev` fields removed from `JitterData`).
- `placeJitterOnDirection` now scans the whole array; on overlap it computes the escape position, gives up (`Number.MAX_VALUE`) only if that escape exceeds `jitter / 2`, otherwise moves `y` further from center and restarts the scan from index 0 so all items are rechecked against the new position — guaranteeing a non-overlapping result whenever one exists in range.
- `fixJitterAvoidOverlaps` picks the direction with smaller movement, falls back to random jitter (within budget) only when the result would exceed `jitter / 2` or the category band half-width, and only then records the new point via `items.push(...)`.
