Migration complete and verified. Here's the structure I generated in `/output`:

```
/output
├── lib/
│   ├── bytes.mjs      — byte utils: UTF-8 encode, hex, concat, u32-BE pack, in-place XOR
│   ├── sha1.mjs       — SHA-1 from scratch, hashlib-shaped, with copy()able state
│   ├── hmac.mjs       — RFC 2104 HMAC, generic over a digest module
│   ├── pbkdf2.mjs     — PBKDF2 as a file-like keystream (pbkdf2.py semantics)
│   └── argparse.mjs   — argparse subset: parsing, help layout, error messages
└── test7.mjs          — entry point, mirrors the Python script line for line
```

**What the black box turned out to be:** `pbkdf2.PBKDF2(pass, salt).read(24)` is PBKDF2-HMAC-SHA1 with 1000 iterations. A stack trace leaked from an invalid-UTF-8 probe confirmed the module (`pbkdf2.py`, `_setup` encoding the passphrase as UTF-8), matching the defaults I inferred from the outputs. `read()` is modeled as a real keystream — buffered leftovers and a persistent block counter — so `read(20)+read(4)` equals `read(24)`, not just the 24-byte case the script needs.

**Argparse fidelity** (each behavior probed against the executable, not assumed):
- `--a v`, `--a=v`, `--a=` (empty), last-wins duplicates, unique-prefix abbreviation (`--hel` → help)
- Value-vs-option classification exactly as argparse: `-5`/`-5.5`/`-` and space-containing strings are values; `-abc`/`--` are option-like → `expected one argument`
- Error precedence: missing-required fires *before* unrecognized-arguments; `-h` fires before both. Exit 2 to stderr, help to stdout, help column computed at width 14 like `HelpFormatter`
- Bare `--` acts as separator but is retained in the leftovers, while `--=x` yields the ambiguity error — both quirks of current argparse, reproduced

**Verification**
- 170/170 differential cases (stdout + stderr + exit code) against `test7_executable`, plus 400/400 randomized fuzz over printable ASCII, unicode, dashes, `=`, tabs, and empty strings
- Primitives independently validated against published vectors: SHA-1 (FIPS 180-2, incl. the 1M-`a` case), HMAC-SHA1 (RFC 2202), PBKDF2 (RFC 6070, incl. multi-block dkLen=25 and embedded NULs)
- ESM-only, `.mjs` throughout, zero npm deps; `node:path` is the only import and it's a built-in. No `node:crypto` anywhere

Two deliberate, unavoidable deviations, both inherent to the runtime rather than the logic: the `prog` token in usage/error text comes from `argv[0]`, so it reads `test7.mjs` instead of `test7_executable` (I derived it dynamically rather than hardcoding the Python binary's name — say the word if you'd rather it be hardcoded for byte-exact stderr). And on invalid UTF-8 argv bytes, Python raises `UnicodeEncodeError` (exit 1) via surrogateescape, whereas Node has already substituted U+FFFD before user code sees the argument, making that path undetectable and so unreplicated.
