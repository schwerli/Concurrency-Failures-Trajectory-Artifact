## Three non-obvious things the black-box probing caught

1. **`format_usage()` collapses its own trailing blank line.** `_format_usage` returns `...\n\n`, but it passes back through `HelpFormatter.format_help()`, which strips it to one `\n`. My first version emitted a blank line before every `error:` message — this alone failed 18 of 37 cases.

2. **argparse re-splits the usage string on a regex before wrapping**, so `--a A` becomes two independently wrappable chunks. At `COLUMNS=34` Python emits `[-h] --a` / `A`, not `[-h]` / `--a A`. Reproduced with `/\(.*?\)+(?=\s|$)|\[.*?\]+(?=\s|$)|\S+/g`.

3. **`--` may never be consumed as an optional's value.** `--a -- x` errors with *expected one argument* rather than taking `--` as the value, because `_get_nargs_pattern` strips the `-` placeholders for optionals. Modeled by building the same `O`/`A`/`-` pattern string over argv and matching `(A)`.

Also worth flagging: `tags=KEYWORD` passes the *class*, not an instance. `Schema.add` instantiates anything callable — reproduced via a `Proxy` `apply` trap so `KEYWORD` works both bare and as `KEYWORD({...})`, with `instanceof` intact.

Two fixes came from the self-tests rather than the diff: whoosh's tokenizers recycle a single `Token` object (harmless in Python list comprehensions, but spreading the generator in JS yielded N references to the same token), so the tokenizers now yield a fresh `Token` per match. And my initial `StopFilter` expectations were wrong, not the code — whoosh renumbers positions from the first *surviving* token's original position, so `'the quick brown fox'` gives `quick@1, brown@2, fox@3`. I corrected the test to match whoosh's actual semantics.
