## Library files

**`/output/lib/pyerrors.mjs`** — Python exception + traceback emulation

```js
/**
 * Minimal emulation of the CPython exception objects that the original script
 * can surface, plus the interpreter's top-level traceback rendering.
 */

/** Equivalent of Python's `ValueError`. */
export class ValueError extends Error {
  constructor(message) {
    super(message);
    this.name = 'ValueError';
    this.pyFrames = [];
  }
}

/** Records a Python-side call frame on an exception as it propagates outward. */
export function addFrame(error, file, line, name) {
  if (error instanceof ValueError) error.pyFrames.push({ file, line, name });
  return error;
}

/** Renders a traceback in CPython's format. */
export function formatTraceback(error, callerFrames = []) {
  const frames = [...callerFrames, ...[...error.pyFrames].reverse()];
  const lines = ['Traceback (most recent call last):'];
  for (const frame of frames) {
    lines.push(`  File "${frame.file}", line ${frame.line}, in ${frame.name}`);
  }
  lines.push(`${error.name}: ${error.message}`);
  return lines.join('\n') + '\n';
}
```

## Verification

I built a differential harness that runs `/workspace/dataset/test7_executable` and `node /output/test7.mjs` on identical argv and compares stdout, exit code, and stderr:

- **482/482** curated cases and **800/800** fuzzed cases match — byte-for-byte on all three streams (the only normalization is the PID in PyInstaller's `[PYI-<pid>:ERROR]` line, which is non-deterministic in the reference itself).
- All four documented sample cases reproduce exactly.
- The AES core independently passes the FIPS-197 Appendix C known-answer vectors for 128/192/256-bit keys.

Probing the reference surfaced four behaviors worth flagging, all now matched:

1. **CBC is stateful** — `data2` chains off `ciphertext1`, not the IV.
2. A `-`-prefixed value is still a value if it's a bare `-`, looks like a negative number, **or contains a space** — this was a genuine bug in my first pass, caught by the fuzzer.
3. `--` is reported as an unrecognized argument and can never supply an option's value (argparse strips `-*` from the nargs pattern for optionals).
4. `-hx` prints help and exits 0, but `-h=x` errors — the `=` separator is what distinguishes them.

Error paths are reproduced too: exit 2 with usage for argparse failures, exit 1 with the `ValueError` traceback for bad key/IV/block sizes.

Two notes on judgment calls: `prog` is hardcoded to `test7_executable` (rather than derived from `test7.mjs`) so usage/error text is byte-identical to the reference — flagging it since it's a deliberate deviation from the literal script name. The traceback omits Python's source-echo lines, matching what the executable prints when `test7.py` isn't in the working directory. Constraints hold: `.mjs` throughout, ESM only, relative imports only, no `node:crypto`.
