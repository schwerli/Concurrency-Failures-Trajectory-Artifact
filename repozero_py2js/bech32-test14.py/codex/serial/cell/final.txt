The migration is implemented in pure Node ESM under `/output`, with only local `.mjs` imports, manual `process.argv` parsing, and a local `convertBits` reimplementation. I verified the 4 provided sample cases plus CLI behaviors for `--help`, missing required args, invalid int values, `--name=value`, duplicate options, and unrecognized arguments against `/workspace/dataset/test14_executable`; the help/error banner is fixed to `test14_executable` so those strings line up as well.

One residual difference remains for post-parse runtime failures: the error type/message are aligned (`ValueError`, `TypeError`), but the full traceback format is still Node’s rather than Python/PyInstaller’s.
