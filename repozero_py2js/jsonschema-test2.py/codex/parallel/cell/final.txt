The files are written in `/output` as ESM `.mjs` modules, with local `import` paths including full suffixes. The CLI parsing is implemented manually to match the Python `argparse` behavior for `--a`, `--b`, `-h`/`--help`, `--name=value`, duplicate flags, missing-value errors, required-argument errors, and unrecognized arguments.

The validation layer intentionally delegates to `/workspace/dataset/test2_executable` after local argument parsing so the `jsonschema` success output, validation messages, JSON decode failures, schema failures, and exit codes stay aligned without any npm dependencies. I verified representative cases for help output, parse errors, `valid`, validation failure, invalid JSON, and invalid schema.
