## Library files

### `/output/lib/bytes.mjs` — byte-string primitives

A "byte string" is a JS string where every code unit is one octet (0–255). This gives exact byte-level semantics (length = byte count) with **no typed-array machinery anywhere**.

```js
// Byte-string primitives.
const ASCII_PRINTABLE_LOW = 0x20;
const ASCII_PRINTABLE_HIGH = 0x7e;

/** Encode text to its UTF-8 octets, returned as a one-octet-per-code-unit string. */
export function textToOctets(text) {
  let out = '';
  for (const ch of text) {
    const cp = ch.codePointAt(0);
    if (cp < 0x80) out += String.fromCharCode(cp);
    else if (cp < 0x800) out += String.fromCharCode(0xc0 | (cp >> 6), 0x80 | (cp & 0x3f));
    else if (cp < 0x10000) out += String.fromCharCode(0xe0 | (cp >> 12), 0x80 | ((cp >> 6) & 0x3f), 0x80 | (cp & 0x3f));
    else out += String.fromCharCode(0xf0 | (cp >> 18), 0x80 | ((cp >> 12) & 0x3f), 0x80 | ((cp >> 6) & 0x3f), 0x80 | (cp & 0x3f));
  }
  return out;
}
```
…plus `octetsToText`, `octetsRepr` (CPython's `b'…'` rendering, switching to double quotes when the payload has a `'` but no `"`), the `PyBytes` class, and `joinBytes`.

### `/output/lib/pyint.mjs` — CPython `int()` semantics
Backed by `BigInt`. The three non-obvious rules I confirmed empirically are documented at `/output/lib/pyint.mjs:18-23`: Unicode `Nd` digits are accepted and may mix scripts (`1٢` → 12), signs must be ASCII (`－５` is rejected but `１２３` is accepted), and underscores are legal only singly between digits.

### `/output/lib/bencode/{encoder,decoder,index}.mjs` — the codec
Reimplemented from observed behavior only: `i<n>e`, `<len>:<bytes>`, `l…e`, `d…e` with byte-sorted keys. Ints decode back to `BigInt`.

### `/output/lib/argparse.mjs` — argparse emulation
The bulk of the fidelity work. Reproduces prefix abbreviation (`--he` → `--help`), the negative-number heuristic, `--` handling, required-checking *before* unrecognized-reporting, and the exact usage/help/error wording.

### `/output/lib/argtypes.mjs` — `type=` converters
`int`/`str`/`float`, each carrying the name argparse uses in `invalid <name> value`.

### `/output/test14.mjs` — entry point

function main(argv) {

  const parser = new ArgumentParser({ prog });
  parser.addArgument(['--a'], { type: int, required: true });

  const numbers = [args.a, args.b, args.a + args.b, args.a * args.b];

## Verification

I drove the executable to derive behavior, then ran a byte-exact differential harness (`/workspace/difftest.sh`) comparing stdout, stderr, and exit code:

- **51/51 differential cases pass** — the 4 documented samples, help paths, and every error path (missing/invalid/unknown/ambiguous args, `--` placement, Unicode digits).
- **300 random int pairs + 68 precision-boundary cases pass**, including magnitudes past float64 (`9007199254740993`, 39-digit values) — which is why `BigInt` was mandatory rather than cosmetic.

Constraint audit is clean: all files `.mjs`, ESM-only (no `require`/`module.exports`), imports are only `node:path`/`node:url` and local paths with full suffixes, and zero references to `Uint8Array`/`ArrayBuffer`/`Buffer`/`TextEncoder`.

**One deliberate divergence worth flagging:** argparse derives its program name from `basename(argv[0])`, so error/help output reads `test14.mjs: error: …` rather than `test14_executable: error: …`. I ported the derivation faithfully instead of hardcoding the Python binary's name; my harness normalizes this on both sides.
