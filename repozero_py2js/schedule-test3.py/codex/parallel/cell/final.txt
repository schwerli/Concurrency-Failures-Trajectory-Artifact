Implemented the Node.js ESM migration in `/output` with no external dependencies and manual `process.argv` parsing.

**Files**
- CLI modules: [prog-name.mjs](/output/lib/cli/prog-name.mjs), [messages.mjs](/output/lib/cli/messages.mjs), [parser.mjs](/output/lib/cli/parser.mjs), [cli/index.mjs](/output/lib/cli/index.mjs)
- Schedule modules: [job.mjs](/output/lib/schedule/job.mjs), [schedule/index.mjs](/output/lib/schedule/index.mjs)
- Entry file: [test3.mjs](/output/test3.mjs)

The entrypoint preserves the Python behavior:
- `--a` is required and parsed as `int`
- `--b` is required and parsed as `str`
- `schedule.every(args.a).minutes` is mirrored so `job.interval` prints identically
- help, missing-argument, invalid-int, unknown-argument, `--flag=value`, negative-int, and `--` handling are all implemented without npm packages

Verification: `node /output/test3.mjs` matched `/workspace/dataset/test3_executable` across representative cases for exit codes and stdout/stderr, with the expected program-name difference in usage/help/error text (`test3.mjs` vs `test3_executable`).
