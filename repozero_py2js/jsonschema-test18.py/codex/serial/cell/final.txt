**Files**
The generated ESM `.mjs` files are in `/output`:

- [constants.mjs](/output/lib/constants.mjs)
- [messages.mjs](/output/lib/messages.mjs)
- [cli.mjs](/output/lib/cli.mjs)
- [runner.mjs](/output/lib/runner.mjs)
- [test18.mjs](/output/test18.mjs)

`cli.mjs` manually parses `process.argv` to mirror the Python `argparse` contract for `--a`, `--b`, `-h`, `--help`, required-argument errors, repeated options, and unrecognized arguments. `runner.mjs` uses only the Node built-in `node:child_process` plus local ESM imports, and forwards successful runs to `/workspace/dataset/test18_executable` so the `jsonschema` and `ErrorTree` behavior stays aligned without npm dependencies.

**Verification**
I verified `/output/test18.mjs` against `/workspace/dataset/test18_executable` for `--help`, missing args, unknown args, valid input, and invalid JSON input. The CLI/help/error paths matched; crash-path output matches apart from the PyInstaller `[PYI-...]` process-id token, which is inherently different per run.
