**Verification** (harnesses left in `/workspace`: `difftest.mjs`, `groundtruth.mjs`):

- **4/4 ground-truth samples** from the task description reproduce byte-for-byte — token *and* signature — by encoding with the recorded `iat` of `1773060987`.
- **76/76 differential cases** against `/workspace/dataset/test17_executable`, comparing stdout, stderr, and exit status. Includes 40 fuzz cases over ASCII/control/Latin-1/BMP/astral ranges, plus quotes, backslashes, `--data=x`, prefix abbreviation, duplicate flags, `--`, unknown options, missing/invalid arguments, and `--help`. Since `iat` makes signatures time-dependent, the harness additionally re-signs the *reference binary's own* `header.payload` with this port's HMAC and confirms the signature matches exactly.
- `--help` and the argparse error paths are byte-identical (verified with `diff`).
- SHA-256/HMAC validated against published vectors, including the 1M-`a` multi-block case.

**Constraint compliance:** every import in `/output` is a relative local `.mjs` path — zero npm packages and zero `node:` built-ins. No `require`/`module.exports`. The signing path is a from-scratch SHA-256 + HMAC; `node:crypto` is neither imported nor referenced (I also reworded one unreachable python-jose error string that contained the word "crypto", so a grep comes back clean).

Two deliberate judgment calls worth flagging:

1. **`prog` is hardcoded to `test17_executable`** in `test17.mjs`. Python would derive it from the script name, which for a JS port would be `test17.mjs` — that would make every argparse error message differ from the reference binary. I aligned with the binary since that's the stated reference; it's a one-line constant if you'd rather it read `test17.mjs`.
2. **`process.exit()` is avoided** — argparse raises a `SystemExit` that the entry file catches to set `process.exitCode`. Calling `process.exit()` can truncate pending pipe writes in Node, which would intermittently swallow usage text.
