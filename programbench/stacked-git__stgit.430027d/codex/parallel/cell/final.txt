Built a clean-room `stg` reimplementation in [src/stg.py](/workspace/src/stg.py), with [compile.sh](/workspace/compile.sh) installing it to `./executable`. It reproduces the observed top-level parser/help/version behavior and a Git-backed stack model using `refs/stacks/<branch>` plus `refs/patches/<branch>/<patch>`, with captured help text stored in [captured/help_texts.json](/workspace/captured/help_texts.json).

I smoke-tested the installed `./executable` for `--help`/`-h`/`--version`, parse errors, non-repo errors, and core repo commands: `init`, `new`, `refresh`, `series`, `top`, `next`, `prev`, `push`, `pop`, `goto`, `delete`, `clean`, `rename`, `hide`, `unhide`, `branch`, `id`, `name`, `files`, `show`, `diff`, `patches`, `log`, `commit`, and `completion list`.

Gap: several less-common subcommands are still explicit stubs rather than matched implementations, including `edit`, `email`, `export`, `float`, `fold`, `import`, `pick`, `pull`, `rebase`, `redo`, `repair`, `reset`, `sink`, `spill`, `squash`, `sync`, `uncommit`, and `undo`.
