Implemented a standalone reimplementation in [src/sevenzip_compat.py](/workspace/src/sevenzip_compat.py) with [compile.sh](/workspace/compile.sh) installing it as `./executable`. It reproduces the CLI surface, help/info text, archive listing/testing/extraction, hashing, and create/update/delete/rename flows using original code plus system `libarchive`/`tar` and Python stdlib, without invoking the provided binary at runtime.

I verified exact parity against the preserved original for `-?`, `i`, unsupported command handling, `l/t/x -so` on original `7z`, `l` on original `zip`/`gz`/`xz`, single-file `h`, `a` for `zip`/`tar`/`gz`/`xz`, and the `tar` `-si` error path. The main remaining risk is exact byte-for-byte/output parity for some `7z` create/update cases and `bzip2` create, where the archive backend still differs from upstream even though the resulting archives are functional.
