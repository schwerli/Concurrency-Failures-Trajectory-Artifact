     1	# CLI surface, flag parsing, version, exit codes
     2	
     3	Binary: `/workspace/executable` (goimports-reviser v3, `3.0.0-20260303205914-9926ea38658f`, built go1.26.0).
     4	All probes run from `/tmp/probe/cli-flags`. Raw run artifacts (stdout/stderr/exit per run) live in
     5	`/tmp/probe/cli-flags/runs/<label>/{out,err,exit}`.
     6	
     7	**RENDERING WARNING:** the log timestamp separator is a **SLASH**, not a dash. `cat -A` in this
     8	environment renders `2026/08/10` as `2026-08-10`. `od -c` proves the real bytes:
     9	
    10	```
    11	0000000   2   0   2   6   /   0   8   /   1   0       1   4   :   1   4
    12	0000020   :   5   4       n   o       f   i   l   e   (   s   )       o
    13	```
    14	
    15	Every `TS` placeholder below means exactly `YYYY/MM/DD HH:MM:SS ` (Go `log` default flags
    16	`LstdFlags = Ldate|Ltime`, trailing single space before the message). Log output goes to **stderr**.

   272	### B15. The stdin hint depends on the KIND of stdin
   273	
   274	`reading from stdin, press Ctrl+D when done...\n` → **stderr, no log timestamp**, printed *before*
   275	the `Paths:` line.
   276	
   277	| stdin | hint printed? |
   278	|---|---|
   279	| `< /dev/null` (char device) | **YES** |
   280	| pty (`script -qec ... /dev/null`) | **YES** |
   281	| closed fd (`0<&-`) | **YES** |
   282	| anonymous pipe (`printf ... \|`) | no |
   283	| named FIFO (`< fifo`) | no |
   284	| regular file (`< in.go`) | no |
   285	
   286	Consistent rule: print when `os.Stdin.Stat()` errors **or** `mode & os.ModeCharDevice != 0`.

   672	## Algorithm inference
   673	
   674	```
   675	func main() {
   676	    // 1. Register the 18 flags (see table). No -h/-help flag is registered.
   677	    flag.Parse()          // ExitOnError:
   678	                          //   -h/-help/--help  -> flag.Usage() to stderr; exit 0
   679	                          //   unknown flag     -> "flag provided but not defined: -X\n" + usage; exit 2
   680	                          //   bad value        -> stdlib msg + usage; exit 2
   681	                          // Parsing STOPS at the first non-flag arg (and consumes a lone "--").
   682	
   683	    // 2. Version short-circuits, BEFORE anything else. version-only wins.
   684	    if *versionOnly { fmt.Fprintf(os.Stdout, "%s\n", version); os.Exit(0) }
   685	    if *version {
   686	        fmt.Fprintf(os.Stdout, "version: %s\nbuilt with: %s\ntag: %s\ncommit: %s\nsource: %s\n",
   687	                    version, goVersion, tag, commit, source)
   688	        os.Exit(0)
   689	    }
   690	
   691	    // 3. Merge targets: positionals first, then the deprecated -file-path (if non-empty).
   692	    paths := flag.Args()
   693	    if *filePath != "" { paths = append(paths, *filePath) }
   694	
   695	    // 4. Empty check (this is BEFORE imports-order validation).
   696	    if len(paths) == 0 {
   697	        flag.Usage()                                     // -> stderr
   698	        log.Fatal("no file(s) or directory(ies) specified on input")   // exit 1
   699	    }
   700	
   701	    // 5. Stdin resolution: ONLY when exactly one target and it is "-".
   702	    if len(paths) == 1 && paths[0] == "-" {
   703	        if fi, err := os.Stdin.Stat(); err != nil || fi.Mode()&os.ModeCharDevice != 0 {
   704	            fmt.Fprintln(os.Stderr, "reading from stdin, press Ctrl+D when done...")
   705	        }
   706	        paths[0] = "<standard-input>"     // content read from stdin; output forced to STDOUT
   707	    }
   708	
   709	    // 6. Parse -imports-order (BEFORE the Paths log).
   710	    order, err := parseOrder(*importsOrder)
   711	    if err != nil { flag.Usage(); log.Fatalf("unknown order group type: %q", badToken) }  // exit 1
   712	
   713	    // 7. Log the target list.
   714	    log.Printf("Paths: %v", paths)
   715	
   716	    // 8. Per target, in argv order (duplicates NOT deduped):
   717	    for _, p := range paths {
   718	        log.Printf("Processing %s", p)
   719	        projName := *projectName
   720	        if projName == "" && !stdinMode-with-projectName {
   721	            projName, err = determineProjectName(p)      // walks up for go.mod
   722	            if err != nil {
   723	                flag.Usage()
   724	                log.Fatalf("Could not determine project name for path %s: %+v", p, err)  // exit 1
   725	            }
   726	        }
   727	        // -output is validated HERE (inside processing), and is SKIPPED entirely in stdin mode:
   728	        //   not in {"file","write","stdout"} -> log.Fatalf("invalid output %q specified", out)  exit 1
   729	        // any processing error -> log.Fatalf("Failed to fix file: %v", err)  exit 1
   730	    }
   731	
   732	    // 9. Deprecation epilogue, AFTER all processing succeeded.
   733	    deprecated := false
   734	    if *filePath != "" {
   735	        log.Print("-file-path is deprecated. Put file name(s) as last argument to the command(Example: goimports-reviser -rm-unused -set-alias -format goimports-reviser/main.go)")
   736	        deprecated = true
   737	    }
   738	    if *local != "" {
   739	        log.Print("-local is deprecated and will be removed soon. Use -company-prefixes instead.")
   740	        deprecated = true
   741	    }
   742	    if deprecated {
   743	        log.Fatal("All changes to file are applied, but command-line syntax should be fixed")  // exit 1
   744	    }
   745	
   746	    // 10. -set-exit-status: exit 1 if any file changed (or, with -list-diff, differed).
   747	    if *setExitStatus && anyChanged { os.Exit(1) }
   748	    os.Exit(0)
   749	}
   750	```

   771	## Surprises / gotchas
   772	
   773	1. **`-` reads STDIN.** Undocumented in the README. Only when it is the *sole* resolved target
   774	   (positional or via `-file-path`). Path token becomes `<standard-input>`; output always goes to
   775	   stdout; no file is written; `-output` is not even validated (`-output bad -` exits 0).
   776	2. **The stdin hint is conditional on stdin's file type** (char device / stat error → printed;
   777	   pipe / FIFO / regular file → not). It is plain `Fprintln` to stderr with **no** log timestamp,
   778	   and it appears *before* the `Paths:` line and even before `-imports-order` validation.
   779	3. **Deprecated flags make a fully successful run exit 1.** `-file-path a.go` formats `a.go`
   780	   correctly and then exits 1 with `All changes to file are applied, but command-line syntax should
   781	   be fixed`. Same for `-local`. This will break naive CI reimplementations.
   782	4. **`-file-path` is still a real target source**, appended *after* the positional args, so
   783	   `-file-path b.go a.go` yields `Paths: [a.go b.go]`.
   784	5. **Empty string values for `-file-path` / `-local` / `-project-name` are treated as unset**
   785	   (no deprecation warning, no target added, no go.mod bypass).
   786	6. **`flag.Usage()` is called on some fatal paths but not others.** Printed for: no-targets,
   787	   `unknown order group type`, `Could not determine project name`. NOT printed for:
   788	   `invalid output`, `Failed to fix file`. This ordering (usage *between* the `Processing` line and
   789	   the fatal line) is easy to get wrong.
   790	7. **`-version-only` beats `-version`** regardless of argv order.
   791	8. **Version output goes to STDOUT** while everything else diagnostic goes to stderr.
   792	9. **Usage goes to STDERR even for `-h`** (Go default), yet `-h` exits **0**.
   793	10. **`Usage of %s:` uses `os.Args[0]` verbatim**, so the header changes with how the binary is
   794	    invoked (`./gir`, `gir`, `/abs/path`). A reimplementation must not hardcode the program name.
   795	11. **`Processing` is logged per command-line target, not per file.** A recursive run over a tree
   796	    with 3 files logs exactly one `Processing .`.
   797	12. **Duplicate targets are not deduplicated** — `a.go a.go` processes it twice and logs twice.
   798	13. **Flags after the first positional become targets** and produce confusing
   799	    `Failed to fix file: open .../-format: no such file or directory` errors — but files listed
   800	    *before* them are still modified on disk first.
   801	14. **The empty-string target** yields `Paths: []` (indistinguishable from an empty slice in the log)
   802	    and `Processing ` with a trailing space, then a distinct error `path is not set`.
   803	15. **`-list-diff` never writes and always exits 0**, so running it twice lists the same file twice;
   804	    pair it with `-set-exit-status` to get exit 1.
   805	16. **Trailing-slash on a nonexistent dir is stripped** in the error message (`nopedir/` →
   806	    `.../nopedir`) but preserved in `Paths:`/`Processing`.
   807	17. **Non-`.go` files are not skipped by extension**; they are parsed and produce
   808	    `file has invalid Go source content, use -excludes flag to skip this file: ...`.
   809	18. **`-excludes` does not suppress the `Processing` line** for an excluded target.
   810	19. The README is stale relative to the binary for `-separate-named`, `-version`, and `-version-only`.

   814	## Open questions
   815	
   816	- The exact `-list-diff` + `-output write` combination (README claims it lists *and* writes) was not
   817	  exercised here; `-list-diff` with default `-output file` demonstrably does **not** write.
   818	- Whether `-set-exit-status` reports "changed" based on content diff or on a write attempt, when
   819	  combined with `-output stdout`, was not isolated.
   820	- The precise semantics of `commit: n/a` (this build has no commit stamped); a build with a real
   821	  commit may format that line differently.
   822	- Whether `-use-cache` alters any of the CLI-visible logging (no difference observed incidentally,
   823	  but not systematically probed).
   824	- Behavior when stdin is a char device that blocks forever (a real interactive TTY) was only
   825	  approximated with `script`; the hint text implies Ctrl+D handling.
   826	- Whether an `os.Stdin.Stat()` error truly drives the hint, or the closed-fd case coincidentally
   827	  reports a char-device-like mode, could not be distinguished without inspecting the binary.
   828	- Multi-target runs where an early target fails: confirmed the process dies immediately
   829	  (`log.Fatalf`), so later targets are never processed — but whether earlier partial writes are
   830	  rolled back was not tested (they are not, based on B18).
