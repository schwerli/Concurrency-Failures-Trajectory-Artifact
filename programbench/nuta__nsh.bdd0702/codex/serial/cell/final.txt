Implemented a fresh replacement shell in [src/nsh_main.py](/workspace/src/nsh_main.py) with its runtime layer in [lib/nsh_init.bash](/workspace/lib/nsh_init.bash); [compile.sh](/workspace/compile.sh) installs it as [executable](/workspace/executable). The reimplementation covers the observed CLI surface, rc loading order, prompt mini-language, command execution via a clean shell backend, command-not-found behavior, the no-TTY warning, and the `.nsh.log` / `.nsh_history` side effects.

I verified it against the provided binary on `--help`, `--version`, `-c`, script execution, rc sourcing, alias expansion, prompt rendering, and representative error cases. One gap remains: syntax-error diagnostics and the missing-file panic path are behaviorally aligned and use the same exit codes, but they are not byte-for-byte identical to the reference binary’s custom parser output and Rust backtrace.
