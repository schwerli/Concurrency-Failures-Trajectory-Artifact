Implemented a clean-room Go reimplementation in [main.go](/workspace/main.go), [parser.go](/workspace/parser.go), [shell.go](/workspace/shell.go), [util.go](/workspace/util.go), with [compile.sh](/workspace/compile.sh) building `./executable`. It reproduces the observed CLI/help/version surface, rc loading order, prompt expansion, alias/env/cwd state, command execution, pipes/redirection, command substitution, arithmetic expansion, and the nonstandard unquoted expansion behavior I measured from the original.

I built it with `./compile.sh` and verified byte-for-byte matches against the preserved original for the main probe set under the same executable basename: `--help`, `--version`, bad-flag handling, repeated `-c`, clustered flags, rc loading, no-arg non-TTY startup, parse errors, `if`/`for`/function one-liners, arithmetic expansion, variable-splitting quirks, `unset`, and representative command failures. Remaining risk is limited to panic backtrace detail on file-open failure paths, where the original emits runtime-generated backtrace text.
